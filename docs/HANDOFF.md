1. 수정은 `test` 저장소에만 합니다. 소스는 계정 안 어디서든 가져와도 됩니다.

4. 고객 입력값은 어디에도 저장하지 않습니다. 저장소가 공개이므로 인증키와 고객 정보를 코드에 넣지 않습니다.
5. 빌드 도구와 모듈(import/export)을 쓰지 않습니다. `index.html`의 script 순서를 바꾸지 않습니다(`docs/DIRECTORY.md`).
6. 새 파일 이름은 영문으로 짓습니다.
7. 요건이 불확실하면 먼저 질문합니다. 사용자는 현재 로직과 문서의 완성도를 80% 이하로 보며, 항목별로 확인해 확정하기를 원합니다.
8. 데이터 출처: 도로명주소 API, 공공데이터포털(건축HUB 건축물대장, HF 월지급금), 브이월드, HF 시세조회 웹(사용자가 내부 협의를 마쳤다고 밝힘).
9. 지점 직원 전용(접속 토큰), 부산·양산 우선 검색을 유지합니다.
10. 서식(동의서, 확약서, 약정서, 등기서류)은 이 저장소의 `forms/` 폴더에서 개발합니다.
11. 코드를 만들면 시험보다 먼저 커밋합니다(사용자 동의). 시험에서 문제가 나오면 추가 커밋으로 고칩니다.

## 6. 사용자와 합의한 요건 요약

### 주택가격 (요건정의 4장)

- 시세 대상은 용도에 "아파트" 또는 "연립"이 있는 주택입니다. 전용면적 차이 1.0㎡ 이내 타입만 목록에 나옵니다.
- 최저층은 하위평균가, 그 밖의 층은 일반평균가를 계산 없이 그대로 씁니다.
- 자동 선택: 면적 차이 0.1㎡ 이내 타입이 있으면 부동산원 → 국민은행 순서. 없으면 가장 가까운 타입을 먼저 골라 두고 상담자가 바꿉니다.
- 다세대주택은 시세 없이 공시가격 환산으로 상담하고 감정평가 후 확정합니다.
- 상담자가 직접 고른 기준이나 입력한 가격은 다른 호를 선택하기 전까지 유지해야 합니다. 현재 코드는 공시가격 조회 완료나 최저층 변경 때 자동 선택값으로 덮어씁니다.

### 담보방식 추천 (요건정의 6장)

- 가족 구성과 소유 형태가 기본 추천을 정하고, 선호 문항은 보조입니다. 추천에는 계량평가 결과와 추천 문구가 함께 나와야 합니다.
- 최종 선택은 고객이 하며 추천과 다르게 고를 수 있습니다. 다르면 그 사실을 표시합니다.
- 승계 위험 판정 기준: 주택 소유자에게 "비공동 자녀"(상대 배우자의 자녀가 아닌 자녀)가 있는가. 소유자는 단독소유면 신청인, 공동소유면 부부 두 사람입니다.
- 조사 항목: 신청인 자녀 유무, 배우자 자녀 유무, 두 사람의 자녀 관계(① 모두 공동자녀 ② 신청인에게만 비공동 자녀 ③ 배우자에게만 비공동 자녀 ④ 두 사람 모두 비공동 자녀). 질문 구조는 단순하게 유지합니다.

| 구분 | 승계 위험 | 귀속 위험 | 기본 추천 |
|---|---|---|---|
| 소유자에게 비공동 자녀가 있음 | 3 | 3 | 신탁(고정) |
| 비공동 자녀가 배우자에게만 있고 신청인 단독소유 | 1 | 2 | 신탁(기본) |
| 무자녀 부부 | 1 | 3 | 신탁(기본) |
| 공동자녀만 있는 부부 | 1 | 1 | 중립 |
| 배우자 없음 + 자녀 있음 | 0 | 0 | 중립 |
| 배우자·자녀 모두 없음 | 0 | 2 | 신탁(기본), 지인은 1인 개별지정 |

- 판정(임시 기준값): 승계 위험 2점 이상이면 신탁 고정. 귀속 위험만 2점 이상이면 신탁이 기본이고 선호 지수가 -40 미만이면 저당권. 그 밖에는 선호 지수 +20 초과 신탁, -20 미만 저당권, 그 사이는 자율 선택.
- 선호 지수 = Σ(응답 × 중요도) ÷ Σ(2 × 중요도) × 100. 응답은 -2(저당권 쪽)~+2(신탁 쪽), 중요도는 0~2.
- 사용자가 직접 정한 것
  - 신청인만 자녀가 있으면 신탁 추천. 배우자 승계를 확보하고, 신청인 자녀를 귀속권리자로 포괄 또는 개별 지정(1인으로 한정하지 않음).
  - 공동자녀 가구와 "배우자 없음 + 자녀 있음"은 위험 측면에서 중립. 장단점을 보여주고 나머지 항목의 고객 선호로 추천.
  - 무자녀 부부는 신탁 기본 추천(고정 아님).
  - 배우자와 자녀가 모두 없으면 다른 큰 요인이 없을 때 신탁과 지인 1인 개별지정 추천(100% 고정할지는 사용자도 확신하지 않음).
- 귀속권리자 지정 규정(신탁방식 설명서 20번)

| 지정방법 | 위탁자 자녀 유무 | 지정 대상 |
|---|---|---|
| 개별지정 | 자녀 있음(①·② 중 하나) | ① 위탁자의 자녀, 자녀의 배우자, 손자녀, 보증약정 이후 혼인한 배우자 가운데 1인 이상 / ② 그 밖의 사람 1인 |
| 개별지정 | 자녀 없음(①·② 중 하나) | ① 위탁자의 3촌 이내 혈족(손자녀, 형제, 조카 등), 2촌 이내 인척(배우자의 자녀 등), 보증약정 이후 혼인한 배우자 가운데 1인 이상 / ② 그 밖의 사람 1인 |
| 포괄지정 | 자녀 있음 | 자녀 전원 |
| 포괄지정 | 자녀 없음 | ① 사후수익자(배우자)의 자녀 전원 ② 위탁자의 형제·자매 전원 ③ 위탁자의 손자녀 전원 가운데 하나. ②, ③은 귀속권리자가 되는 사람 중 1인 이상의 개인정보 제공 동의 필요 |

## 7. v6.1 설계 (구현됨. 아래와 다르면 코드가 우선)

### 시세 자동 선택 (`js/price.js`)

- `bestSise()`: `siseNear()` 결과에서 면적 차이 0.1㎡ 이내 타입을 고르고, 그중 `source === '부동산원'`이 있으면 가장 가까운 것, 없으면 나머지 중 가장 가까운 것. 0.1㎡ 이내 타입이 없으면 전체에서 가장 가까운 것.
- `buildPriceOptions()` 끝부분: 상담자가 고른 상태(`S.userBase`)이고 그 선택지가 목록에 있으면 `S.base`를 그대로 둡니다.
- `S.userBase`를 켜는 곳: `js/main.js`의 `$('priceBase').onchange`, `$('housePrc').oninput`. 끄는 곳: `js/building.js`의 `resetUnit()`.

### Step 5 담보방식 추천 (새 파일 `js/collateral.js`)

- 화면: `index.html`의 `</div><!-- /.consult-wrap -->` 바로 앞에 Step 5 영역을 넣습니다. 기존 "Step 5. 주택연금 신청서"는 Step 6으로, 화면 표기는 v6.1로 바꿉니다.
- script 순서: common → api → customer → building → price → pension → application → collateral → main. `main.js` 끝에서 초기화 함수를 부릅니다.
- 다시 묻지 않고 가져오는 값
  - 신청인 생년월일 `ownerBirth`, 배우자 생년월일 `spouseBirth` (나이는 부부 중 연소자 기준)
  - 배우자 유무: `spouseBirth`, `sp_name`, `sp_ssn` 중 하나라도 값이 있으면 있음(`updateDocList`와 같은 기준)
  - 평가주택가격 `housePrc`, 주택유형 `house_type`, 사용승인일 `S.det.useAprDay` 또는 `S.bld.useAprDay`
  - 소유 구분: 신청서의 `input[name="ownership"]`(값 `단독`/`공동`)과 같은 값으로 묶음
- 새로 받는 값: 자녀 질문 3개, 보증금 있는 임대차 건수, 신탁을 쓸 수 없는 주택 여부, 선호 6문항, 주택가격상승률(연 %).
- 결과 화면: 추천 제목과 한 줄 문구, 가족 구성·소유 형태, 승계 위험과 귀속 위험 점수, 선호 지수, 추천 사유, 확인할 사항, 두 방식의 알아둘 점, 귀속권리자 지정 안내.

- `updateDocList()` 첫머리에서 추천을 다시 계산하게 하면 앞 단계 값이 바뀔 때 함께 갱신됩니다.
- 이용 제한
  - 신탁을 쓸 수 없는 주택(복합용도주택, 농지법 등으로 신탁이 제한되는 주택, 등기와 실질이 다른 주택)이면 "저당권방식만 가능".
  - 보증금 있는 임대차가 5건 이상이고 단독주택이 아니면 "추천 보류". 1건 이상이면 저당권방식 이용 제한 가능성을 안내만.
- 재건축: 건물 경과연수 + 기대여명이 30년 초과면 안내, 40년 초과면 경고와 6번 문항 중요도 1 → 2. 기대여명 표는 기존 추천 도구의 `LIFE_EXPECTANCY`(60세 미만 25, 90세 초과 3).
- 설정세금 참고값: 주택가격 × (1 + 상승률/12)^((101 - 나이) × 12)를 백만 원 단위로 내린 뒤 × 0.12%. 기존 도구의 식이며 검증하지 않았습니다.
- 선호 문항: 6개 모두 기존 도구의 문구를 옮겼고, 4번은 금액과 "0원" 표현을 뺐습니다. 문구는 사용자와 확정해야 합니다.
- 기존 도구에서 빼는 것: "배우자 없음 + 자녀 있음"의 저당권 강제, 임대차 5건 이상 "가입 불가", 무자녀 부부의 5번 문항 보정.
- 계산은 화면을 건드리지 않는 함수 `colEval()` 하나에 있어 Node에서 따로 시험할 수 있습니다. 시험 결과: 시세 선택 7개, 추천 판정 43개 모두 통과.

## 9. 알려진 문제와 주의점

- Worker 캐시: 건축물대장 7일 캐시가 `workers.dev` 주소에서는 꺼지게 되어 있어 현재 작동하지 않습니다(배포본 `/api/health`: `version v6.2`, `cache:false`, 키 3개 등록, `needToken:true`). 사용자는 도메인이 없고, 조회한 주소가 7일간 남는 KV 캐시는 허용했습니다. 그러나 KV 읽기·쓰기도 요청당 외부 호출 50회에 포함되어 아래 한도 문제는 KV로 풀리지 않습니다. 도메인·KV 도입은 보류입니다.
- **대단지 조회 한도(보류 중인 작업)**: 대단지에서 `외부 호출 한도(50회) 근접` 오류가 납니다. 한도는 API 호출 1건마다 새로 계산됩니다. 유력한 원인은 `/api/bld/unit`·`/api/bld/units`의 동·호 표기 변형 반복과 `hubFetch`의 4회 재시도입니다(실제 실패 단계는 미확인). 수정안: 재시도 상한 낮추기, 표기 변형 줄이기, 예산(예: 40회) 소진 시 `partial`로 돌려주고 화면이 이어서 요청. Worker와 화면(`js/building.js`, `js/main.js`)을 함께 고쳐야 하며 Worker 배포는 사용자가 합니다. 자세한 내용은 요건정의 11장 5번.
- 화면(GitHub Pages)과 Worker(Cloudflare)는 별개입니다. 화면 코드(`index.html`, `css/`, `js/`)는 main에 올리면 자동 반영되고 Cloudflare에 올릴 것이 없습니다. Worker는 API 경로나 응답이 바뀔 때만 배포합니다.
- Worker는 `https://windstorm2.github.io`에서 온 요청만 허용합니다. 내 PC에서 화면을 열면 API 호출이 막힙니다.
- 접속 토큰 없이는 조회 기능을 시험할 수 없습니다. 사용자가 개발용 화면에서 상담 1건을 끝까지 진행해 확인해야 합니다.
- 연금 산출
  - 초기증액형의 감액 후 금액은 API 값이 아니라 최초 금액 × 70%로 코드에서 계산합니다.
  - 대출상환방식은 인출금이 한도를 넘으면 자동 전환됩니다(설명서상 대출 상환 용도 전용).
  - 정기증가형과 확정기간혼합방식은 없습니다. 대출상환우대방식은 "별도 산출" 안내만 띄웁니다.
- 공시가격 × 보정비율(기본 140%)은 공사의 평가 순서에 없는 참고용 추정치입니다.
- 기존 비교안 문서(backup)의 오류
  - 조카와 배우자의 자녀를 개별지정 ②로 적었으나 규정상 ①입니다.
  - ①을 "1인"으로 적었으나 "1인 이상"입니다.
  - 무자녀 부부에 형제자매가 개입한다고 적었으나, 민법 제1003조상 자녀와 부모가 없으면 배우자가 단독 상속합니다.
- **대지권 서비스(해결 중)**: 브이월드 `ldaregList`는 사용자가 실제 키로 호출해 작동을 확인했습니다(2026-11-24, 응답 필드는 요건정의 3.1). 기존 Worker v6.2는 `ldragsList`로 불러 실패했을 가능성이 큽니다. `worker/worker.js`에서 `ldaregList`로 고쳤습니다(v6.3). 이후 아파트에서만 대지권 비율이 안 나온다는 보고로 v6.4에서 쪽 읽기(`totalCount` 기준)와 앞자리 0 매칭을 고치고 실패 사유 표시를 넣었습니다. v6.4는 배포되어 화면에 새 문구가 나오는 것을 확인했습니다. 남천동 단지(대단지 아님)에서 "대지권등록 조회 실패(브이월드 응답 없음)"이 나와 v6.5에서 호출 방식을 바꿔 재시도하고 실패 사유를 자세히 보이게 했습니다. **v6.5는 아직 배포 전입니다(배포는 사용자).** 배포 방법: 대시보드의 Workers & Pages → `homepension` → Edit code에서 기존 코드를 지우고 `worker/worker.js` 내용을 붙여 넣은 뒤 Deploy. 배포 확인: `/api/health`의 `version`이 `v6.5`. 그 뒤 아파트(동·호 선택)로 확인합니다. 비율이 안 나오면 화면 위쪽 상태 표시의 "대지권 비율 없음: …" 문구(읽은 건수, 동 예시)를 알려 주세요. 브라우저에서 `ldaregList`를 `numOfRows=500`으로 불러 응답에 들어온 행 수와 `numOfRows` 값을 보면 브이월드가 건수를 제한하는지도 알 수 있습니다.
- 대지권 비율 추정은 사용자 결정으로 화면 코드에서 뺐습니다(2026-11-23). `js/building.js`의 `syncBuildingToApplication`은 대지권 분자가 없으면 신청서 "대지" 면적 칸에 전체 대지면적을 넣습니다. 이것도 비워야 하는지는 확인 전입니다.
- 신탁방식의 비용 지원은 한시적입니다(HF 안내).
- AI 작업 환경: 임시 작업 공간이 대화 사이에 초기화됩니다. 코드를 만들면 바로 커밋해야 합니다.
