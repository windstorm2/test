# 요건정의 (적용 로직 전체)

버전: v0.2 초안 / 최종 수정: 2026-11-22

이 문서는 아직 확정본이 아닙니다. 프로젝트 환경을 구성한 뒤 항목별로 검토해 확정합니다.

각 항목 앞의 표시는 다음을 뜻합니다.

- `[코드]` 기존 코드에서 확인한 현재 동작
- `[합의]` 논의로 정한 방향
- `[초안]` 제안 단계이며 값이나 기준이 정해지지 않음
- `[미확인]` 아직 코드를 줄 단위로 읽지 않아 적지 못한 부분 (v0.2 기준 남은 항목 없음. 단, 담보방식 추천 도구와 Worker의 세부 계산식은 요약 수준입니다.)

원본 파일은 `backup/202611222155/`에 있습니다.

## 1. 전체 흐름

`[합의]` 신청인 정보 → 주택정보 검색 → 연금액 산출 → 담보방식 선택 → 맞춤형 설명서 → 신청서 교부 및 서류 안내 → 서류 출력(개인정보 동의서, 확약서, 약정서, 등기서류)

`[합의]` 같은 정보는 한 번만 입력합니다. 모든 단계와 서식은 하나의 공통 데이터를 읽고 씁니다.

## 4. 주택가격 산정 `[코드]`

### 4.1 가격 기준의 종류

| 기준 | 목록에 나오는 조건 | 적용 가격 |
|---|---|---|
| 시세(부동산원, KB) | 건축물 용도에 "아파트" 또는 "연립"이 있고, HF 시세조회 결과 중 전용면적 차이가 1.0㎡ 이내인 타입 | 최저층이면 하위평균가, 아니면 일반평균가(해당 값이 없으면 다른 쪽 값) |
| 공시가격 환산 | 공시가격이 조회된 경우 | 공시가격 × 보정비율(기본 140%, 입력 범위 100~200%) |
| 직접 입력 | 항상 | 상담자가 입력한 값 |

### 4.2 자동 선택 순서

1. 조건에 맞는 시세 타입이 있으면 전용면적이 가장 가까운 타입을 고릅니다. 면적 차이가 같을 때만 부동산원을 KB보다 먼저 고릅니다.
2. 시세가 없고 공시가격이 있으면 공시가격 환산을 고릅니다.
3. 둘 다 없으면 직접 입력이 됩니다.
4. 평가주택가격 칸에 값을 직접 치면 기준이 "직접 입력"으로 바뀝니다.

### 4.3 최저층 판정

선택한 호의 층이 1층이거나, 건축물대장에 있는 지상층 가운데 가장 낮은 층이면 "예"로 자동 설정합니다. 상담자가 바꿀 수 있습니다.

### 4.4 공시가격 조회

올해 자료를 먼저 찾고, 없으면 전년도 자료를 찾습니다. 한 해에 최대 30쪽까지 조회하며, 동의 순서와 층으로 해당 호가 있을 쪽을 추정해 그 주변부터 2쪽씩 찾습니다.

### 4.5 안내와 제한

- 공시가격이 12억 원을 넘으면 "가입요건 확인 필요" 경고를 띄우고 계산은 계속합니다.
- 평가주택가격이 12억 원을 넘으면 월지급금이 12억 원 상한으로 산정된다고 안내합니다.
- 건축물 용도에 "오피스텔" 또는 "업무시설"이 있으면 연금을 산출하지 않고 공사 홈페이지 또는 담당자 산출로 안내합니다.
- 공시가격 환산과 직접 입력은 감정평가 결과에 따라 연금액이 달라질 수 있다고 안내합니다.

### 4.6 검토가 필요한 사항

1. 시세 타입을 면적이 가까운 순서로 고르기 때문에, KB 타입의 면적이 더 가까우면 부동산원보다 KB가 먼저 선택됩니다. 공사의 가격 적용 순서와 대조해야 합니다.
2. 다세대주택은 시세 대상에서 빠집니다(용도에 "아파트" 또는 "연립"이 있어야 함). 의도한 것인지 확인이 필요합니다.
3. 시세 타입이 있으면 선택 목록을 다시 만들 때마다(최저층 변경, 공시가격 조회 완료) 자동 선택으로 되돌아갑니다. 상담자가 고른 다른 타입이나 직접 입력한 값이 바뀔 수 있습니다. 코드를 읽어 확인한 것이며 실행해 보지는 않았습니다.
4. 보정비율 기본값 140%의 근거를 적어 둘 필요가 있습니다.

## 5. 연금액 산출 `[코드]`

1. 인출금이 없으면 종신지급, 있으면 종신혼합으로 계산합니다.
2. 기초연금 수급, 1주택, 2.5억 미만 여부가 "아니오"가 아님, 평가주택가격 2억 5천만 원 미만을 모두 만족하면 우대형으로 계산합니다. 평가주택가격이 2억 5천만 원 이상이면 일반형으로 계산하고 그 사실을 안내합니다.
3. 인출금이 한도를 넘으면 대출상환방식으로 바꾸고, 그 한도도 넘으면 한도액으로 낮춥니다.
4. 대출상환우대방식은 API가 지원하지 않아 "별도 산출" 안내만 합니다.
5. 정액형과 초기증액형(3년, 5년, 7년, 10년) 5종을 비교합니다.
6. 초기증액형의 감액 후 금액은 API 값이 아니라 최초 금액 × 70%로 코드에서 계산합니다.

## 6. 담보방식 추천

### 6.1 현재 도구의 동작 `[코드]`

- 성향 질문 6개(명의 유지, 배우자 승계, 임대 활용, 초기 세금, 사후 정산, 재건축 대처)를 각각 -2~+2점, 가중치 0~2로 받아 -100~+100 지수를 만듭니다.
- 지수가 -20 미만이면 저당권 권장, +20 초과면 신탁 권장, 그 사이는 "신탁방식 권장(자율선택 가능)"으로 표시합니다.
- 임대차 5건 이상이면 가입 불가로 끝냅니다.
- 배우자가 없고 자녀가 있으면 저당권으로 강제합니다.
- 건물 경과연수 + 기대여명이 30년을 넘으면 재건축 가능성 안내, 40년을 넘으면 경고와 함께 재건축 문항 가중치를 1에서 2로 올립니다.
- 저당권 예상 설정세금: 주택가격 × (1 + 상승률/12)^((101 - 나이) × 12)을 백만 원 단위로 내린 뒤 0.12%를 곱합니다. 화면에는 "50% 감면 기준 예상치"로 표시합니다.
- 가족 구성(5개 CASE)은 경고문과 귀속권리자 안내에만 쓰이고 최종 판정에는 거의 반영되지 않습니다.

### 6.2 개정 방향 `[합의]`

1. 추천까지의 단계는 가족 구성과 소유 형태가 기본 추천을 정하고, 성향 응답은 보조로 씁니다.
2. 최종 선택은 고객이 하며 추천과 다른 방식도 고를 수 있습니다.
3. 추천에는 이를 뒷받침하는 계량평가 결과와 추천 문구가 함께 나와야 합니다.
4. 가입자만 자녀가 있는 경우: 신탁방식을 추천합니다(배우자 승계 확보). 귀속권리자는 가입자 자녀를 대상으로 포괄지정 또는 개별지정하며, 1인으로 한정하지 않습니다.
5. 공동자녀 가구: 배우자 승계와 상속 위험 측면에서는 중립으로 보고 두 방식의 장단점을 보여줍니다. 비용 부담, 소유권 이전에 대한 심리적 저항 등 나머지 항목의 응답 결과로 한쪽을 추천합니다.
6. 배우자와 자녀가 모두 없는 경우: 비용 등 다른 큰 요인이 없으면 신탁방식과 지인 1인 귀속권리자 개별지정을 추천합니다. 이를 예외 없이 고정할지는 정하지 않았습니다.
7. 배우자가 없고 자녀가 있는 경우: 승계와 상속 위험 측면에서는 중립으로 봅니다. 나머지 항목에서 고객 선호가 확인되면 그 방식을 추천합니다. (현재 도구의 저당권 강제는 없앱니다.)
8. 배우자가 있고 가입자 단독소유인 경우: 가입자 사망 시 배우자 승계는 공동소유와 같게 봅니다. 그 밖의 부분은 가족 구성별로 따로 검토합니다.

### 6.3 위험 평가표 `[초안]`

"저당권방식을 고를 때의 위험"을 두 항목(각 0~3점)으로 계산해 화면에 보여주는 안입니다. 점수는 임시값입니다.

| 가족 구성 | 승계 위험 | 귀속 위험 | 기본 추천 | 귀속권리자 안내 |
|---|---|---|---|---|
| 가입자만 자녀 있음 | 3 | 3 | 신탁 | 가입자 자녀 대상 포괄지정 또는 개별지정 |
| 부부 각각 자녀 있음 | 3 | 3 | 신탁 | 가족 합의로 대표 지정 또는 포괄지정 |
| 자녀 없는 부부 | 2 | 3 | 신탁 | 신뢰하는 1인 |
| 배우자만 자녀 있음 | 2 | 2 | 신탁 | 배우자 자녀 |
| 배우자·자녀 모두 없음 | 0 | 2 | 신탁(다른 큰 요인이 없을 때) | 지인 등 1인 개별지정 |
| 공동자녀 부부 | 1 | 1 | 중립, 성향 응답으로 추천 | 신탁 선택 시 안내 |
| 배우자 없음 + 자녀 있음 | 0 | 0 | 중립, 성향 응답으로 추천 | 신탁 선택 시 안내 |

- 승계 위험 2점 이상이면 신탁 추천을 고정하고, 귀속 위험만 2점 이상이면 성향이 뚜렷하게 저당권 쪽일 때 추천이 바뀌는 안입니다. 기준값(성향 지수 -40 미만 등)은 정하지 않았습니다.
- 공동자녀 가구도 저당권방식은 배우자 승계 때 자녀 등 공동상속인의 동의가 필요합니다([HF 담보제공방식 비교](https://www.hf.go.kr/ko/sub03/sub03_01_02_02.do)). 중립으로 두더라도 저당권의 단점으로 표시하는 안입니다.

### 6.4 검토가 필요한 사항

1. 위험 점수와 성향 지수 기준값
2. 소유 형태(단독/공동)에 따른 차이. 배우자가 먼저 사망할 때 공동소유는 지분 상속이 생기고 단독소유는 생기지 않는다는 점은 추론이며 확인이 필요합니다.
3. 귀속권리자 지정 규정. 기존 비교안은 조카를 "개별지정 ②"로 적었으나 같은 문서의 규정 요약으로는 3촌 이내 혈족이라 ①에 해당합니다. 신탁 관련 규정 원문과 대조해야 합니다.
4. 신탁방식 비용. 기존 비교안은 "공사 전액 지원"으로 적었으나 HF 안내는 가입자 부담이 원칙이고 현재 한시적으로 공사가 지원한다고 되어 있습니다.
5. 신탁 이용 제한 주택(복합용도주택, 농업인 주택 등)과 임대차 5건 제한의 단독주택 예외가 도구에 없습니다.
6. 기존 명세서와 코드의 차이: 자녀 없는 부부의 5번 문항 보정은 코드에만 있고, 재건축 가중치 보정은 명세서("2 이상")와 코드("1일 때만 2로")가 다릅니다.

## 7. 맞춤형 설명서

미개발입니다. 요건을 정하지 않았습니다.

## 8. 신청서와 필요서류 안내 `[코드]`

### 8.1 신청서 반영

- 연금 비교표에서 [신청서 반영]을 누르면 지급방식이 신청서에 들어갑니다. 종신지급과 종신혼합은 지급유형(정액형, 초기증액형 3·5·7·10년)까지 채웁니다. 대출상환, 우대지급, 우대혼합은 해당 체크 항목이 있으면 체크합니다.
- 조회한 주택 정보는 주택주소, 주택유형, 면적에 들어갑니다. 주택유형은 건축물 용도로 정합니다: 오피스텔 → 주거용오피스텔, 노인복지 → 노인복지주택, 아파트 → 아파트, 연립·다세대 → 연립/다세대, 단독·다가구 → 단독주택.
- 인출 용도별 금액을 넣으면 인출금 총액에서 뺀 나머지가 "기타" 칸에 자동으로 들어갑니다.
- 신청인과 배우자의 주소는 "담보주택과 같음"을 체크하면 주택주소로 채웁니다.

### 8.2 필요서류 판정

기본 서류(조건 없이 항상 표시)

| 대상 | 주민센터 발급 | 기타 |
|---|---|---|
| 신청인 | 주민등록등본 2부, 주민등록초본 1부(전 주소 포함), 전입세대확인서 1부, 가족관계증명서(상세) 1부, 인감증명서 2부 | 인감도장 및 신분증, 등기권리증 원본(소지한 경우) |
| 배우자(있을 때) | 가족관계증명서(상세) 1부, 인감증명서 1부 | 인감도장 및 신분증 |

조건에 따라 달라지는 서류

| 조건 | 판정 기준 | 달라지는 내용 |
|---|---|---|
| 배우자 있음 | 배우자 생년월일, 성명, 주민등록번호 중 하나라도 입력 | 배우자 서류 칸 표시 |
| 신탁방식 | 담보제공방식이 신탁(포괄) 또는 신탁(개별) | 신청인 지방세 납세증명서 1부 추가, 발급 요건 안내문 표시 |
| 신탁방식 + 공동소유 | 위 조건 + 소유 구분 "공동" | 배우자 지방세 납세증명서 1부 추가 |
| 공동소유 | 소유 구분 "공동" | 배우자 인감증명서 2부로 변경, 배우자 주민등록초본 1부(전 주소 포함) 추가 |
| 부부 주소 다름 | 둘 다 "담보주택과 같음"이 아니고 주소 글자도 다름 | 배우자 주민등록등본 1부 추가 |
| 우대형 | 8.3 참조 | 기초연금수급자격확인서 1부 추가 |
| 주거용 오피스텔 | 주택유형이 주거용오피스텔이거나 용도 조회 결과가 오피스텔 | 지방세 세목별 과세증명서 1부 추가 |
| 선순위대출 상환 | 인출 용도 "선순위대출상환" 금액이 0보다 큼 | 대출잔액증명서 1부 추가 |

신탁등기용 지방세 납세증명서 안내문: ① 주민등록번호 전체 표시 ② 사용목적 "부동산 신탁등기" 체크 ③ 신탁부동산 표시에 담보주택 주소 표시

목록은 화면에 표시하고 글자로 복사할 수 있습니다.

### 8.3 우대형 판정(서류 목록용)

다음 중 하나면 우대형으로 봅니다.

1. 신청서 지급방식에 "우대"가 들어간 항목이 체크됨
2. 연금 산출 결과가 우대형
3. 기초연금 수급 "예", 1주택 "예", 2.5억 미만 여부가 "아니오"가 아님, 평가주택가격이 0보다 크고 2억 5천만 원 미만

### 8.4 검토가 필요한 사항

1. 서류를 바꾸는 조건은 위 표가 전부입니다. 임대차가 있는 경우, 대리 신청, 신탁 귀속권리자 관련 서류에 대한 조건은 코드에 없습니다. 실제로 필요한지는 업무 기준으로 확인해야 합니다.
2. 담보제공방식과 소유 구분을 고르기 전에는 근저당권, 단독소유 기준으로 표시됩니다.
3. 배우자 유무를 Step 1의 생년월일과 신청서의 성명·주민등록번호 세 곳에서 판정합니다. 통합할 때는 공통 데이터의 한 값으로 정리해야 합니다.

## 10. 개인정보

`[합의]` 고객 정보는 저장하지 않습니다.

`[코드]` 메인 도구가 브라우저에 남기는 값은 지점 접속 토큰(`branchToken`)과 공시가격 보정비율(`ratio`) 두 가지입니다. 신청서에는 주민등록번호와 연락처 입력란이 있으나 저장하는 코드는 없습니다.

## 11. 운영 제약 `[코드]`

1. Worker는 요청 1건당 외부 호출을 46회로 제한합니다(무료 한도 50회 대응).
2. 건축물대장 7일 캐시는 Worker 주소가 `workers.dev`로 끝나면 꺼집니다. 현재 주소가 `homepension.windstorm2.workers.dev`라 캐시가 작동하지 않습니다.
3. Worker는 등록된 출처 외에 `.workers.dev`로 끝나는 모든 출처의 호출을 허용합니다. 접근 통제는 지점 접속 토큰이 맡습니다.
4. 주소 검색은 시·도를 생략하면 부산과 경남 양산을 먼저 찾습니다. 지점 직원 전용으로 유지합니다.
