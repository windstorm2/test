# 요건정의 (적용 로직 전체)

버전: v0.6 초안 / 최종 수정: 2026-11-24 18:00

이 문서는 아직 확정본이 아닙니다. 프로젝트 환경을 구성한 뒤 항목별로 검토해 확정합니다.

각 항목 앞의 표시는 다음을 뜻합니다.

- `[코드]` 기존 코드에서 확인한 현재 동작
- `[합의]` 논의로 정한 방향
- `[초안]` 제안 단계이며 값이나 기준이 정해지지 않음
- `[미확인]` 아직 코드를 줄 단위로 읽지 않아 적지 못한 부분 (v0.2 기준 남은 항목 없음. 단, 담보방식 추천 도구와 Worker의 세부 계산식은 요약 수준입니다.)
- `[규정]` 공사 「주택연금 설명서 및 체크리스트」 저당권방식(서식2)과 신탁방식(서식2-2)에서 확인한 내용. 두 서식 모두 개정 2026.5.18., 시행 2026.6.1.이며 원본 PDF는 저장소에 올리지 않았습니다.

원본 파일은 `backup/202611222155/`에 있습니다. 메인 도구를 나눈 코드는 `index.html`, `css/`, `js/`에 있고 구성은 `docs/DIRECTORY.md`에 적었습니다.

### 3.1 대지권 비율 수집 `[합의]` `[코드]`

- `[합의]` 대지권 비율은 자료가 있을 때만 수집하고, 없으면 비워 둡니다. 면적 비례 추정은 하지 않습니다(2026-11-23). v6.1 이후 코드에서 추정을 뺐습니다(`js/building.js`의 `computeBestLandRight`). 추정으로 채우던 값은 화면에 "(추정)"으로 표시되었습니다.
- 수집 순서: 브이월드 대지권등록 → 건축물대장 전유부(`ldaQotaAr`, `ldaQotaRate`) → 브이월드 공동주택속성(`getApartHousingPriceAttr`). 모두 없으면 빈 칸입니다.
- `[코드]` 브이월드 대지권등록목록조회는 `/ned/data/ldaregList`(요청 변수 `pnu`, `key`)이며, 사용자가 실제 키로 호출해 작동을 확인했습니다(2026-11-24). 응답 필드: `buldDongNm`(동), `buldFloorNm`(층), `buldHoNm`(호), `ldaQotaRate`(대지권 비율, "분자/분모", 예 `81.03/15622.1`은 15622.1분의 81.03), `buldNm`(건물명), `clsSeCodeNm`("현재" 등), `lastUpdtDt`. 한 필지에 여러 동·호가 한꺼번에 나옵니다(시험 필지 129건). 동 `0000`·호 `0000`은 건물 단위 행이고, 상가는 동 이름이 `상가지상1층`처럼 들어옵니다. 요청으로 동·호를 걸러낼 수 없어 필지 전체를 페이지로 읽고 Worker가 동·호를 맞춰 찾습니다.
- `[코드]` 기존 Worker v6.2는 이 서비스를 `ldragsList`라는 이름으로 불러 호출이 실패했을 가능성이 큽니다. v6.3에서 `ldaregList`로 고쳤습니다.
- `[코드]` (2026-11-24) 사용자가 "다세대는 대지권 비율이 나오는데 아파트는 안 나온다"고 보고했습니다. 코드에서 찾은 유력한 원인(실제 서버 동작은 미확인): v6.3은 한 쪽에 받은 행이 500건 미만이면 읽기를 멈추는데, 브이월드가 `numOfRows=500`보다 적게(예: 100건) 돌려주는 서비스면 행이 많은 아파트 단지에서는 첫 쪽의 호만 찾고 나머지는 실패합니다(가짜 서버 시험에서 재현). 또 동·호에 앞자리 0이 붙은 표기(`0101`, `01203`)는 매칭 점수가 0이었습니다. v6.4에서 (1) 첫 쪽에서 받은 건수와 응답의 `totalCount`로 끝까지 읽기(6쪽씩 병렬, 호출 38회에서 중단), (2) 앞자리 0 무시, (3) 응답에 진단 정보 `ldareg`(읽은 쪽·행 수, 전체 건수, 동 예시, 중단 사유)를 넣어 화면의 토지 상태 표시에 대지권 비율이 없는 사유를 보이게 했습니다.
- `[코드]` (2026-11-24) v6.4 배포 후 부산 수영구 남천동 단지(대단지 아님, 101동 102호)에서 "대지권등록 조회 실패(브이월드 응답 없음)"이 나왔습니다. 같은 키로 토지 면적(`ladfrlList`)은 받았으므로 키 문제가 아니라 `ldaregList` 호출 하나가 HTTP 오류이거나 JSON이 아닌 응답을 받은 것입니다. 사용자의 성공 시험(`format=xml`, `numOfRows=10`, `domain` 있음)과 Worker 호출(`format=json`, `numOfRows=500`, `domain` 없음)의 차이 세 가지 중 무엇이 원인인지는 확인하지 못했습니다. v6.5는 실패하면 조건을 바꿔 다시 시도하고(JSON 500건 → JSON 100건 → XML 100건, 성공한 방식을 이후 쪽에도 사용), 모두 실패하면 시도마다 HTTP 상태와 응답 앞부분(키는 가림)을 화면에 보입니다. 읽는 필드와 분자/분모 해석은 기존 코드가 이미 맞아 이름만 바꿨고, 응답 형식의 가짜 데이터로 시험했습니다(`10동 1033호` → `15622.1분의 81.03`, 동·호 표기 변형 3종, 없는 호는 빈 값). 실제 배포 후 확인은 남았습니다. JSON 응답(`format=json`)의 최상위 구조는 직접 보지 못했고, 목록을 어떤 구조에서도 꺼내는 기존 `extractVworldRows`에 의존합니다.

## 4. 주택가격 산정 `[코드]`

### 4.1 가격 기준의 종류

| 기준 | 목록에 나오는 조건 | 적용 가격 |
|---|---|---|
| 시세(부동산원, KB) | 건축물 용도에 "아파트" 또는 "연립"이 있고, HF 시세조회 결과 중 전용면적 차이가 1.0㎡ 이내인 타입 | 최저층이면 하위평균가, 아니면 일반평균가(해당 값이 없으면 다른 쪽 값) |
| 공시가격 환산 | 공시가격이 조회된 경우 | 공시가격 × 보정비율(기본 140%, 입력 범위 100~200%) |
| 직접 입력 | 항상 | 상담자가 입력한 값 |

### 4.2 자동 선택 순서

1. (v6.1) 전용면적 차이가 0.1㎡ 이내인 시세 타입이 있으면 그 가운데 부동산원을, 없으면 국민은행(KB) 타입을 고릅니다(가장 가까운 것). 0.1㎡ 이내인 타입이 없으면 목록 전체에서 면적이 가장 가까운 타입을 고르고 출처 우선순위는 적용하지 않습니다.
2. 시세가 없고 공시가격이 있으면 공시가격 환산을 고릅니다.
3. 둘 다 없으면 직접 입력이 됩니다.
4. 평가주택가격 칸에 값을 직접 치면 기준이 "직접 입력"으로 바뀝니다. (v6.1) 상담자가 고른 기준이나 직접 입력한 가격은 다른 호를 선택하기 전까지 유지합니다.

### 4.3 최저층 판정

선택한 호의 층이 1층이거나, 건축물대장에 있는 지상층 가운데 가장 낮은 층이면 "예"로 자동 설정합니다. 상담자가 바꿀 수 있습니다.

### 4.4 공시가격 조회

올해 자료를 먼저 찾고, 없으면 전년도 자료를 찾습니다. 한 해에 최대 30쪽까지 조회하며, 동의 순서와 층으로 해당 호가 있을 쪽을 추정해 그 주변부터 2쪽씩 찾습니다.

### 4.5 안내와 제한

- 공시가격이 12억 원을 넘으면 "가입요건 확인 필요" 경고를 띄우고 계산은 계속합니다.
- 평가주택가격이 12억 원을 넘으면 월지급금이 12억 원 상한으로 산정된다고 안내합니다.
- 건축물 용도에 "오피스텔" 또는 "업무시설"이 있으면 연금을 산출하지 않고 공사 홈페이지 또는 담당자 산출로 안내합니다.
- 공시가격 환산과 직접 입력은 감정평가 결과에 따라 연금액이 달라질 수 있다고 안내합니다.

### 4.6 공사의 평가 기준 `[규정]`

- 신청접수일 기준으로 ① 한국부동산원 인터넷 시세 ② 국민은행 인터넷 시세 ③ 공시가격(없으면 시가표준액) ④ 공사와 협약한 감정평가업자의 최근 6개월 이내 감정평가액을 차례로 적용합니다. 신청인이 요구하면 ④를 먼저 적용할 수 있습니다.
- 주거목적 오피스텔에는 한국부동산원 시세를 적용하지 않습니다.
- 아파트에 한해 담보물건조사서의 담보가액을 적용할 수 있습니다.
- 인터넷 시세를 적용할 때 최저층은 하한평균가를, 그 외 층은 부동산원 시세의 상한평균가와 하한평균가의 산술평균 또는 국민은행 시세의 일반평균가를 적용합니다.
- 감정평가 비용은 신청인이 부담합니다. 주택가격 2억 5천만 원 미만 1주택자이고 적용할 인터넷 시세가 없으면 공사가 감정평가수수료를 지원합니다. 감정평가 결과를 받은 뒤 감정평가를 취소하거나 보증약정을 철회하면 고객이 부담합니다.
- 주택가격이 12억 원을 넘으면 12억 원으로 보고 지급금액을 정합니다.

### 4.7 개정 방향 `[합의]`

1. 전용면적 차이가 0.1㎡ 이내인 시세 타입이 있으면 그 가운데 한국부동산원 타입을 먼저 고르고, 부동산원 타입이 없으면 국민은행 타입을 고릅니다. (분할본까지의 코드는 면적 차이가 완전히 같을 때만 부동산원을 먼저 골랐습니다. v6.1에서 고쳤습니다.)
2. 0.1㎡ 이내인 타입이 없으면 출처 우선순위를 적용하지 않습니다. 1.0㎡ 이내 타입은 지금처럼 선택 목록에 모두 표시하고, 상담자가 필요하면 바꿉니다. `[초안]` 이때 처음 선택해 두는 값은 현재처럼 면적이 가장 가까운 타입으로 합니다.
3. 최저층이 아닌 층의 가격은 HF 시세조회 결과의 일반평균가를 계산 없이 그대로 씁니다. 상한가와 하한가의 평균이 이미 반영된 값입니다. 현재 동작을 유지합니다.
4. 다세대주택은 감정평가 대상이라 시세를 쓰지 않습니다. 상담할 때는 공시가격 환산으로 안내하고 감정평가 뒤에 확정합니다. 현재 동작을 유지합니다.

`[코드]` 1~2번은 v6.1에서 반영했습니다(`js/price.js`의 `bestSise()`). 3~4번은 기존 동작을 유지합니다. Node 계산 시험(7개)만 거쳤고 실제 조회로는 확인하지 못했습니다.

### 4.8 검토가 필요한 사항

1. 공시가격 환산(공시가격 × 보정비율)은 공사 적용 순서에 있는 방식이 아니라 상담용 추정치입니다. 기본값 140%의 근거를 적어 둘 필요가 있습니다.
2. (v6.1에서 해결) 시세 타입이 있으면 선택 목록을 다시 만들 때마다 자동 선택으로 되돌아가던 문제를, 상담자가 직접 고른 기준이나 입력한 가격을 `S.userBase`로 표시해 다른 호를 선택하기 전까지 유지하도록 고쳤습니다. 실제 조회로 확인하지는 못했습니다.
3. 현재 코드는 건축물 용도에 "오피스텔"이 있으면 연금을 산출하지 않습니다. 규정상 주거목적 오피스텔은 부동산원 시세만 적용하지 않으므로, 산출 대상에 넣을지 정해야 합니다.
4. 다세대주택처럼 감정평가로 확정되는 주택을 상담할 때 감정평가수수료 지원 조건을 화면에 안내할지 정해야 합니다.

## 5. 연금액 산출 `[코드]`

1. 인출금이 없으면 종신지급, 있으면 종신혼합으로 계산합니다.
2. 기초연금 수급, 1주택, 2.5억 미만 여부가 "아니오"가 아님, 평가주택가격 2억 5천만 원 미만을 모두 만족하면 우대형으로 계산합니다. 평가주택가격이 2억 5천만 원 이상이면 일반형으로 계산하고 그 사실을 안내합니다.
3. 인출금이 한도를 넘으면 대출상환방식으로 바꾸고, 그 한도도 넘으면 한도액으로 낮춥니다.
4. 대출상환우대방식은 API가 지원하지 않아 "별도 산출" 안내만 합니다.
5. 정액형과 초기증액형(3년, 5년, 7년, 10년) 5종을 비교합니다.
6. 초기증액형의 감액 후 금액은 API 값이 아니라 최초 금액 × 70%로 코드에서 계산합니다.

### 5.1 설명서와 대조한 결과 `[규정]`

일치하는 부분

- 초기증액형은 정한 기간(3년, 5년, 7년, 10년) 뒤부터 초기 월지급금의 70% 수준을 받습니다. 코드의 × 70% 계산과 같습니다.
- 우대형 요건은 본인 또는 배우자가 기초연금 수급권자(65세 이상)이고 부부 기준 2억 5천만 원 미만 1주택만 소유한 경우입니다.

검토가 필요한 부분

1. 종신지급(혼합)방식의 지급유형에는 정기증가형(최초 월지급금은 정액형보다 적고 3년마다 4.5%씩 증가)이 있습니다. 현재 비교표에는 없습니다.
2. 확정기간혼합방식(10년, 15년, 20년, 25년, 30년형. 부부 중 연소자 나이에 따라 고를 수 있는 기간이 다름)은 신청서 선택 항목에는 있으나 연금 산출 규칙에는 없습니다.
3. 대출상환방식은 상환대상 대출(담보주택을 담보로 받은 대출, 폐업예정 소상공인의 대출, 피상속인인 부모의 주택연금 대출)을 갚는 용도로만 쓰고, 인출한도는 대출한도의 50% 초과 90% 이하입니다. 현재 코드는 인출금이 한도를 넘으면 대출상환방식으로 바꾸는데, Step 1의 인출금에는 용도 입력이 없습니다. 용도를 확인하는지 코드를 다시 봐야 합니다.
4. 종신혼합방식의 인출한도는 대출한도의 50%(재건축 등 분담금 납부자금은 70%)입니다. 신탁방식 설명서에는 임대차보증금 반환 용도로 최초 지급과 동시에 인출하면 90%까지 된다는 내용이 있고, 저당권방식 설명서에는 없습니다. 담보방식에 따라 인출한도가 달라질 수 있습니다.
5. 확정기간혼합, 대출상환, 대출상환우대, 우대지급(혼합)방식은 정액형만 고를 수 있습니다. 이 방식으로 계산될 때 비교표가 초기증액형을 빼는지 코드를 다시 봐야 합니다.

## 6. 담보방식 추천

### 6.1 현재 도구의 동작 `[코드]`

- 성향 질문 6개(명의 유지, 배우자 승계, 임대 활용, 초기 세금, 사후 정산, 재건축 대처)를 각각 -2~+2점, 가중치 0~2로 받아 -100~+100 지수를 만듭니다.
- 지수가 -20 미만이면 저당권 권장, +20 초과면 신탁 권장, 그 사이는 "신탁방식 권장(자율선택 가능)"으로 표시합니다.
- 임대차 5건 이상이면 가입 불가로 끝냅니다.
- 배우자가 없고 자녀가 있으면 저당권으로 강제합니다.
- 건물 경과연수 + 기대여명이 30년을 넘으면 재건축 가능성 안내, 40년을 넘으면 경고와 함께 재건축 문항 가중치를 1에서 2로 올립니다.
- 저당권 예상 설정세금: 주택가격 × (1 + 상승률/12)^((101 - 나이) × 12)을 백만 원 단위로 내린 뒤 0.12%를 곱합니다. 화면에는 "50% 감면 기준 예상치"로 표시합니다.
- 가족 구성(5개 CASE)은 경고문과 귀속권리자 안내에만 쓰이고 최종 판정에는 거의 반영되지 않습니다.

### 6.2 개정 방향 `[합의]`

1. 추천까지의 단계는 가족 구성과 소유 형태가 기본 추천을 정하고, 성향 응답은 보조로 씁니다.
2. 최종 선택은 고객이 하며 추천과 다른 방식도 고를 수 있습니다.
3. 추천에는 이를 뒷받침하는 계량평가 결과와 추천 문구가 함께 나와야 합니다.
4. 가입자만 자녀가 있는 경우: 신탁방식을 추천합니다(배우자 승계 확보). 귀속권리자는 가입자 자녀를 대상으로 포괄지정 또는 개별지정하며, 1인으로 한정하지 않습니다.
5. 공동자녀 가구: 배우자 승계와 상속 위험 측면에서는 중립으로 보고 두 방식의 장단점을 보여줍니다. 비용 부담, 소유권 이전에 대한 심리적 저항 등 나머지 항목의 응답 결과로 한쪽을 추천합니다.
6. 배우자와 자녀가 모두 없는 경우: 비용 등 다른 큰 요인이 없으면 신탁방식과 지인 1인 귀속권리자 개별지정을 추천합니다. 이를 예외 없이 고정할지는 정하지 않았습니다.
7. 배우자가 없고 자녀가 있는 경우: 승계와 상속 위험 측면에서는 중립으로 봅니다. 나머지 항목에서 고객 선호가 확인되면 그 방식을 추천합니다. (현재 도구의 저당권 강제는 없앱니다.)
8. 배우자가 있고 가입자 단독소유인 경우: 가입자 사망 시 배우자 승계는 공동소유와 같게 봅니다. 그 밖의 부분은 가족 구성별로 따로 검토합니다.
9. 가족 구성은 신청인 자녀 유무, 배우자 자녀 유무, 두 사람의 자녀 관계 세 가지로 조사하고 배우자 유무와 함께 봅니다. 기본 유형은 무자녀, 가입자 자녀, 배우자 자녀, 공동자녀, 각각 자녀 5가지입니다. 유형은 필요 이상으로 늘리지 않되 필요하면 나눕니다. 승계 위험은 6.3의 "비공동 자녀" 기준으로 판정합니다.
10. 질문 항목과 구조는 중요한 부분을 놓치지 않는 범위에서 단순하게 합니다. 조건이 붙은 질문이 복잡하게 이어지는 것을 피합니다.
11. 무자녀 부부: 신탁방식을 기본 추천으로 합니다. 고정은 아니며 성향이 뚜렷하게 저당권 쪽이면 추천이 바뀝니다.

### 6.3 가족 구성 판정 기준 `[합의]`

두 방식의 차이가 생기는 지점 `[규정]`

- 저당권방식: 소유자가 사망하면 6개월 안에 주택 지분 전부를 배우자 앞으로 소유권 이전등기하고 채무인수를 해야 합니다. 자녀 등에게 주택의 일부라도 상속 등으로 이전되면 변제해야 합니다. 부부 공동소유에서 배우자가 사망하거나 이혼한 경우에도 6개월 안에 한 사람에게 지분 전부가 이전되지 않으면 지급정지 사유가 됩니다.
- 신탁방식: 배우자(사후수익자)가 6개월 안에 채무인수만 하면 되고 공동상속인의 동의가 필요 없습니다. 다만 공동상속인이 유류분 반환을 청구하면 배우자에게 가액반환 책임이 생길 수 있습니다.

판정 기준

- "비공동 자녀"는 상대 배우자의 자녀가 아닌 자녀를 말합니다.
- 승계 위험(저당권방식을 고를 때)은 주택 소유자에게 비공동 자녀가 있는지로 판정합니다. 소유자는 단독소유면 신청인, 공동소유면 부부 두 사람입니다. 소유자가 사망하면 그 지분을 배우자와 소유자의 자녀가 함께 상속하므로, 남은 배우자의 자녀가 아닌 상속인의 동의가 필요해지기 때문입니다.
- 이 기준이면 5가지 유형을 늘릴 필요가 없습니다. 기존 분류와 결과가 달라지는 곳은 아래 표의 두 칸입니다.

| 가족 구성 | 신청인 단독소유 | 부부 공동소유 |
|---|---|---|
| 가입자만 자녀 | 높음 | 높음 |
| 각각 자녀(공동자녀 없음) | 높음 | 높음 |
| 공동자녀 + 신청인만의 자녀 | 높음 | 높음 |
| 공동자녀 + 배우자만의 자녀 | 낮음(달라지는 칸) | 높음 |
| 배우자만 자녀 | 낮음(달라지는 칸) | 높음 |
| 공동자녀만 | 낮음 | 낮음 |
| 무자녀 | 낮음(소유자의 부모가 생존하면 높아짐) | 낮음(소유자의 부모가 생존하면 높아짐) |

- "낮음"인 경우에도 저당권방식은 상속인인 자녀 전원의 동의가 필요합니다. 저당권의 단점으로 표시합니다.
- 달라지는 두 칸의 이유: 신청인이 사망하면 상속인은 배우자와 신청인의 자녀뿐이고, 배우자가 먼저 사망해도 단독소유라 주택 상속이 생기지 않습니다. 배우자의 비공동 자녀는 신청인의 상속인이 아닙니다.
- 무자녀 부부: 소유자에게 자녀와 부모가 모두 없으면 배우자가 단독으로 상속합니다(민법 제1003조). 소유자의 부모가 생존해 있으면 부모가 배우자와 함께 상속인이 됩니다. `[초안]` 부모 생존 여부는 따로 묻지 않고, 무자녀 부부에게 이 내용을 안내문으로 보여줍니다.
- 이 절의 상속 관계는 민법의 상속 순위(제1000조, 제1003조)를 적용한 것이며 법률 검토를 거치지 않았습니다.

조사 방법 `[초안]`

| 순서 | 질문 | 답 | 묻는 조건 |
|---|---|---|---|
| 1 | 신청인에게 자녀가 있습니까 | 예 / 아니오 | 항상 |
| 2 | 배우자에게 자녀가 있습니까 | 예 / 아니오 | 배우자가 있을 때 |
| 3 | 두 분의 자녀 관계는 어떻습니까 | ① 모두 두 분의 공동자녀 ② 신청인에게만 공동자녀가 아닌 자녀가 있음 ③ 배우자에게만 공동자녀가 아닌 자녀가 있음 ④ 두 분 모두 공동자녀가 아닌 자녀가 있음 | 1, 2가 모두 "예"일 때 |

- 기존 도구의 세 번째 질문(공동자녀 여부, 예/아니오)을 네 가지 선택으로 바꾼 것입니다. 질문 수는 늘지 않습니다.
- 신청인에게 비공동 자녀가 있는 경우: 1이 "예"이고 2가 "아니오"이거나, 3의 답이 ② 또는 ④.
- 배우자에게 비공동 자녀가 있는 경우: 1이 "아니오"이고 2가 "예"이거나, 3의 답이 ③ 또는 ④.
- 승계 위험이 높은 경우: 신청인에게 비공동 자녀가 있거나, 부부 공동소유이면서 배우자에게 비공동 자녀가 있는 경우.

### 6.4 위험 평가표 `[초안]`

"저당권방식을 고를 때의 위험"을 두 항목(각 0~3점)으로 계산해 화면에 보여주는 안입니다. 점수는 임시값입니다.

- 승계 위험: 소유자가 사망했을 때 배우자가 연금을 이어받지 못할 가능성
- 귀속 위험: 부부가 모두 사망한 뒤 남는 재산이 원하는 사람에게 가지 않을 가능성. 저당권방식에서는 나중에 사망한 사람의 상속인이 받으므로, 비공동 자녀가 있거나 자녀가 없으면 사망 순서에 따라 받는 사람이 달라집니다.

| 구분 | 승계 위험 | 귀속 위험 | 기본 추천 |
|---|---|---|---|
| 소유자에게 비공동 자녀가 있음 | 3 | 3 | 신탁(고정) |
| 비공동 자녀가 배우자에게만 있고 신청인 단독소유 | 1 | 2 | 신탁(기본). 성향이 뚜렷하게 저당권 쪽이면 바뀜 |
| 무자녀 부부 | 1(소유자의 부모가 생존하면 높아짐) | 3 | 신탁(기본). 성향이 뚜렷하게 저당권 쪽이면 바뀜 |
| 공동자녀만 있는 부부 | 1 | 1 | 중립. 장단점을 보여주고 성향 응답으로 추천 |
| 배우자 없음 + 자녀 있음 | 0 | 0 | 중립. 성향 응답으로 추천 |
| 배우자·자녀 모두 없음 | 0 | 2 | 신탁(다른 큰 요인이 없을 때) |

- 승계 위험 2점 이상이면 신탁 추천을 고정하고, 귀속 위험만 2점 이상이면 성향이 뚜렷하게 저당권 쪽일 때 추천이 바뀌는 안입니다. 기준값(성향 지수 -40 미만 등)은 정하지 않았습니다.

신탁방식을 추천할 때 문구에 함께 넣을 내용 `[규정]`

- 공동상속인이 유류분 반환을 청구하면 배우자에게 가액반환 책임이 생길 수 있습니다.
- 귀속권리자가 아닌 상속인은 신탁이 끝날 때 신탁재산에 대한 권리가 없습니다. 신탁등기가 끝난 재산에 대한 유증은 효력이 없습니다.
- 귀속권리자는 가입 후에도 바꾸거나 추가로 지정할 수 있습니다(비용은 위탁자 부담).
- 가입 후에도 조건변경으로 저당권방식과 신탁방식을 서로 바꿀 수 있습니다.

귀속권리자 지정(신탁방식 설명서 20번)

- 위탁자가 신탁계약을 하면서 지정합니다. 부부가 모두 위탁자(공동소유)이면 각자 자기 지분의 귀속권리자를 지정합니다.

- 포괄지정은 대상자 전원을 지정하며 인적사항을 적지 않습니다. 귀속비율은 균등합니다.

- 가입자만 자녀, 부부 공동소유: 신청인 지분은 위와 같습니다. 배우자 지분은 배우자가 지정하며, 사후수익자(신청인)의 자녀 전원 포괄지정 또는 2촌 이내 인척인 신청인의 자녀 1인 이상 개별지정을 할 수 있습니다.
- 배우자·자녀 모두 없음: 지인은 개별지정 ②에 해당해 1인만 지정할 수 있습니다. 형제나 조카는 개별지정 ①(1인 이상) 또는 형제·자매 전원 포괄지정이 됩니다.

### 6.6 검토가 필요한 사항

1. 무자녀 부부에서 소유자의 부모 생존 여부를 묻지 않고 안내문으로만 처리하는 안(6.3). 기존 비교안은 "부모가 없으면 형제자매가 개입해 상속협의를 거부할 수 있다"고 적었으나, 민법 제1003조에 따르면 자녀와 부모가 없을 때 배우자가 단독으로 상속하므로 형제자매는 상속인이 되지 않습니다. 법률 확인이 필요합니다.
2. 6.3의 질문 3 선택지 문구. 고령 고객이 이해하기 쉬운 표현으로 다듬어야 합니다.
3. 위험 점수와 성향 지수 기준값.
4. 기존 비교안의 귀속권리자 문구 가운데 규정과 다른 곳: 조카를 개별지정 ②로 적음(3촌 이내 혈족이라 ①). 배우자의 자녀를 개별지정 ②로 적음(2촌 이내 인척이라 ①). ①을 "1인 지정"으로 적음(1인 이상). 보증약정 이후 혼인한 배우자와 손자녀 전원 포괄지정이 빠져 있음.
5. 설정 비용. 기존 비교안은 신탁방식을 "공사 전액 지원"으로 적었으나 설명서는 가입자 부담이 원칙이고 공사가 예산 범위에서 지원할 수 있다고 되어 있습니다. 현재 실제 지원 범위를 확인해 문구를 정해야 합니다.
6. 임대차. `[합의]` (2026-11-23 사용자 확인) 보증금 있는 임대차가 1건 이상이어도 순수 월세 계약으로 변경하는 조건이면 저당권방식으로 가입할 수 있으므로 원천 차단 요소가 아닙니다. 다만 조건부 취급이라 신탁방식을 쓰기 어려운 경우에 한해 제한적으로 저당권방식을 추천합니다. 코드에 반영했습니다(6.7). 기존 도구는 임대차 5건 이상이면 가입 불가로 끝냈습니다. 설명서의 4건 이하 제한은 신탁방식의 보증금 있는 임대차에 대한 것이고 단독주택은 예외입니다. 저당권방식은 가입 후 보증금 있는 임대를 할 수 없습니다. 가입 시점에 보증금 있는 임대차가 있는 주택을 저당권방식으로 받을 수 있는지는 설명서에 없어 확인이 필요합니다.
7. 신탁방식을 쓸 수 없는 주택(복합용도주택 등)은 추천 전에 걸러 저당권방식만 안내해야 합니다. (v6.1에서 "신탁을 쓸 수 없는 주택" 질문으로 구현함.)
8. 재건축. 신탁방식은 기한 전에 저당권방식으로 바꿔야 하는 경우가 있습니다. 재건축 문항의 설명과 가중치 보정에 반영할지 정해야 합니다.
9. 기존 명세서와 코드의 차이: 자녀 없는 부부의 5번 문항 보정은 코드에만 있고, 재건축 가중치 보정은 명세서("2 이상")와 코드("1일 때만 2로")가 다릅니다.

`js/collateral.js`가 6.2~6.4의 합의안을 구현했습니다. 계산은 화면을 건드리지 않는 `colEval(inp)` 하나에 있어 Node에서 따로 시험할 수 있습니다. 기준값은 모두 임시값입니다.

- 가족 구성: 6.4 표의 6개 유형으로 판정합니다. 소유자는 단독소유면 신청인, 공동소유면 부부 두 사람이며, 소유자에게 비공동 자녀가 있으면 승계 위험 3·귀속 위험 3으로 신탁을 고정합니다.
- 판정 순서: ① 신탁을 쓸 수 없는 주택이면 "저당권방식만 가능"(임대차가 있으면 순수 월세로 변경하는 조건을 함께 안내) ② 보증금 있는 임대차 5건 이상이고 단독주택이 아니면 신탁을 이용할 수 없으므로 "저당권방식 (조건부)"(순수 월세로 변경하는 조건) ③ 신탁 고정 ④ 귀속 위험이 높은 유형은 신탁이 기본이고 선호 지수가 -40 미만이면 저당권 ⑤ 그 밖에는 선호 지수 +20 초과 신탁, -20 미만 저당권, 그 사이 자율 선택.
- 임대차 반영: 신탁방식을 쓸 수 있고 보증금 있는 임대차가 1건 이상이면 ④·⑤에서 저당권방식이 나와도 "신탁방식 추천 (임대차 반영)"으로 바꾸고 사유를 표시합니다. 선호가 뚜렷하지 않은 "자율 선택"은 그대로 두고 확인할 사항에 임대차 조건만 안내합니다(이 처리가 맞는지는 사용자 확인 전).
- 선호 지수 = Σ(응답 × 중요도) ÷ Σ(2 × 중요도) × 100. 배우자가 없으면 2번 문항을 뺍니다.
- 재건축: 건물 경과연수 + 기대여명이 30년 초과면 안내, 40년 초과면 경고와 함께 6번 문항 중요도가 "보통"일 때 "중요"로 올려 계산합니다.
- 저당권 설정세금 참고값: 6.1의 식을 그대로 썼고 검증하지 않았습니다.
- 추천 결과 화면: 추천 제목과 한 줄 문구, 가족 구성·소유 형태, 두 위험 점수, 선호 지수, 추천 사유, 확인할 사항, 두 방식의 알아둘 점, 귀속권리자 지정 안내.
- 최종 선택: 버튼 3개(`근저당권`, `신탁(포괄)`, `신탁(개별)`)가 신청서의 `collateral_type`을 바꾸고, 추천과 다르면 경고를 표시합니다.
- 기존 도구에서 뺀 것: 배우자 없음 + 자녀 있음의 저당권 강제, 임대차 5건 이상 "가입 불가", 무자녀 부부의 5번 문항 보정.
- 확인한 것: Node 계산 시험 43개, 가상 화면(jsdom)에서 6개 사례의 추천 결과와 최종 선택 반영. 확인하지 못한 것: 실제 브라우저의 화면 모양과 인쇄, 앞 단계(조회)에서 값이 넘어오는 동작.

## 8. 신청서와 필요서류 안내 `[코드]`

### 8.1 신청서 반영

- 연금 비교표에서 [신청서 반영]을 누르면 지급방식이 신청서에 들어갑니다. 종신지급과 종신혼합은 지급유형(정액형, 초기증액형 3·5·7·10년)까지 채웁니다. 대출상환, 우대지급, 우대혼합은 해당 체크 항목이 있으면 체크합니다.
- 조회한 주택 정보는 주택주소, 주택유형, 면적에 들어갑니다. 주택유형은 건축물 용도로 정합니다: 오피스텔 → 주거용오피스텔, 노인복지 → 노인복지주택, 아파트 → 아파트, 연립·다세대 → 연립/다세대, 단독·다가구 → 단독주택.
- 인출 용도별 금액을 넣으면 인출금 총액에서 뺀 나머지가 "기타" 칸에 자동으로 들어갑니다.
- 신청인과 배우자의 주소는 "담보주택과 같음"을 체크하면 주택주소로 채웁니다.

### 8.3 우대형 판정(서류 목록용)

다음 중 하나면 우대형으로 봅니다.

### 8.4 검토가 필요한 사항

1. 서류를 바꾸는 조건은 위 표가 전부입니다. 임대차가 있는 경우, 대리 신청, 신탁 귀속권리자 관련 서류에 대한 조건은 코드에 없습니다. 실제로 필요한지는 업무 기준으로 확인해야 합니다.
2. 담보제공방식과 소유 구분을 고르기 전에는 근저당권, 단독소유 기준으로 표시됩니다.
3. 배우자 유무를 Step 1의 생년월일과 신청서의 성명·주민등록번호 세 곳에서 판정합니다. 통합할 때는 공통 데이터의 한 값으로 정리해야 합니다.

4. `[규정]` 신탁방식은 신탁부동산에 국세 및 지방세 체납이 있으면 가입이 제한됩니다. 현재 목록은 지방세 납세증명서만 추가합니다. 국세 납세증명서가 필요한지 확인해야 합니다.

## 11. 운영 제약 `[코드]`

1. Worker는 요청 1건당 외부 호출을 46회로 제한합니다(무료 한도 50회 대응).
2. 건축물대장 7일 캐시는 Worker 주소가 `workers.dev`로 끝나면 꺼집니다. 현재 주소가 `homepension.windstorm2.workers.dev`라 캐시가 작동하지 않습니다(배포본 `/api/health`의 `cache:false`로 확인). 사용자는 도메인을 보유하지 않으며, 조회한 주소가 7일간 남는 KV 캐시는 허용하기로 했습니다. 다만 KV 읽기·쓰기도 요청당 외부 호출 50회에 포함되므로 아래 5번의 요청당 한도 문제는 KV로 해결되지 않습니다.
3. Worker는 등록된 출처 외에 `.workers.dev`로 끝나는 모든 출처의 호출을 허용합니다. 접근 통제는 지점 접속 토큰이 맡습니다.
4. 주소 검색은 시·도를 생략하면 부산과 경남 양산을 먼저 찾습니다. 지점 직원 전용으로 유지합니다.
5. 대단지에서 `외부 호출 한도(50회) 근접` 오류가 날 수 있습니다(사용자가 확인한 현상). 한도는 상담 1건이 아니라 API 호출 1건마다 새로 계산됩니다. 코드를 읽고 추정한 원인(실제 실패 단계는 미확인): `/api/bld/unit`이 동 표기 최대 6가지 × 호 표기 2가지를 조회하고 실패하면 `bldUnit`이 같은 방식으로 다시 시도함, `/api/bld/units`가 동 표기 변형마다 최대 2쪽에 동 없이 3쪽을 더 조회함, `hubFetch`가 실패 시 최대 4회 재시도하며 재시도도 횟수에 포함됨. 수정 방향(미착수): 재시도 상한 낮추기, 표기 변형 줄이기, 예산(예: 40회)이 다 되면 `partial`로 돌려주고 화면이 이어서 요청. Worker 배포가 필요하며 화면 쪽(`js/building.js`, `js/main.js`)도 함께 고쳐야 합니다.
